## Overview

This project benchmarks symmetric cryptography implementations with a reproducible workflow and a software engineering approach.

Evaluation is performed across three dimensions:

- performance (latency and throughput),
- robustness (avalanche effect),
- cross-platform behavior (Windows x86 vs Raspberry Pi ARM).

Outputs are generated by versioned scripts, validated with KAT (Known Answer Tests), and exported as CSV and charts.

## DevSecOps Controls

DevSecOps practices are implemented through automated validation, statistical quality gates, and security checks across local and CI workflows.

### Why this matters

In this project, performance numbers are only meaningful if implementation correctness and measurement stability are continuously verified. The DevSecOps layer is used to prevent silent regressions, detect data-quality drift early, and keep evidence reproducible from one run to the next.

### Validation and CI

- Unit and integration tests via `pytest`.
- KAT validation using NIST/RFC vectors plus Twofish reference vectors.
- IC95 quality-gate audit in CI via:

```bash
python scripts/audit/audit_ic95.py --enforce-gates
```

- Security automation through CodeQL, Bandit, pip-audit, and Dependabot.

Main workflows:

- `.github/workflows/tests.yml`
- `.github/workflows/security.yml`

### Quantum and AI readiness perspective

- Quantum readiness: the project does not assume immediate practical breaks of modern symmetric cryptography, but it prepares migration discipline through crypto-agility practices, repeatable validation, and evidence-based comparison across algorithm choices.
- AI risk readiness: the main near-term risk is operational misuse rather than new cryptanalysis. Automated checks reduce exposure to configuration errors, vulnerable dependencies, and unnoticed implementation drift.
- Practical outcome: the repository keeps a verifiable baseline that can support future transitions, including post-quantum planning for asymmetric components while maintaining robust symmetric controls.

## Technical Scope

### Algorithms

| Algorithm | Family | Supported key sizes |
|---|---|---|
| DES | Block cipher | 56 bits |
| 3DES | Block cipher | 128 / 192 bits |
| AES | Block cipher | 128 / 192 / 256 bits |
| Twofish | Block cipher | 128 / 192 / 256 bits |
| ChaCha20 | Stream cipher | 256 bits |

### Modes

| Mode | Applicability | Notes |
|---|---|---|
| ECB | Block ciphers | Included for educational comparison only |
| CBC | Block ciphers | IV required |
| CTR | Block ciphers | Nonce required, parallelizable |
| GCM | Block ciphers | AEAD mode (confidentiality + integrity) |
| StreamMode | ChaCha20 | Stream wrapper |

## Project Architecture

| Layer | Main components | Responsibility |
|---|---|---|
| Application | `ExperimentController` | Orchestrates experimental campaigns |
| Domain | `EncryptionEngine`, primitives, modes | Unified encryption/decryption abstractions |
| Execution | `scripts/*.py` | Runs benchmarks, KAT, charts, and audits |

Execution flow:

1. A script in `scripts/` launches a campaign.
2. `ExperimentController` iterates over algorithm/mode/key/message combinations.
3. `EncryptionEngine` delegates to the selected primitive and mode.
4. Results are aggregated and exported to `data/results/*.csv`.
5. Chart and audit scripts consume those CSV files.

## Quick Start

Run all commands from `crypto-experiments/`:

```bash
# 1) Functional validation (KAT)
python scripts/run_kat.py

# 2) Experimental benchmark campaign
python scripts/experiment.py

# 3) Chart generation
python scripts/run_charts.py
```

Optional targeted chart generation:

```bash
python scripts/run_charts.py 01
python scripts/run_charts.py 02
python scripts/run_charts.py 03
python scripts/run_charts.py 04
```

## Data and Reproducibility

- Raw CSV runs are stored in `crypto-experiments/data/results/`.
- Charts are exported to `crypto-experiments/data/charts/`.
- Audit evidence is stored in `crypto-experiments/data/evidence/`.

To reproduce the full process on a new machine:

1. Install dependencies.
2. Run `python scripts/run_kat.py`.
3. Run `python scripts/experiment.py`.
4. Run `python scripts/run_charts.py`.

For cross-platform comparison charts, ensure both Windows and Raspberry Pi CSV files are present in `crypto-experiments/data/results/`.
